# 栞・既読位置サーバー同期 API仕様

このフォークの「栞同期の設定」機能は、複数端末間で以下の4つを共有します。

- **栞(bookmarks)**: 明示的に「ブックマーク追加」した名前付きマーカー。1ファイルに複数件あってよい。
- **既読位置(read_position)**: ページを閉じるたびに自動で保存される「現在の読書位置」。1ファイルにつき常に1件のみ。
- **履歴(history)**: 最近開いたファイルの一覧。栞と同じ形のデータだが、1ファイルにつき常に1件のみ(開き直すたびに上書き)。
- **書庫管理(library)**: 「書庫管理」タブに表示する、SMB共有上のアーカイブファイル一覧(カタログ)。栞/既読位置/履歴とは異なり「誰の」データでもない単一のカタログ(hostキーを持たない)で、カタログの中身を作る(スキャンする)処理はアプリ自身ではなく**サーバー運用者側が別途用意するスキャナーの責務**になる。

対象は**SMBサーバー上のファイルのみ**(端末ローカルのファイルは同期対象外。書庫管理のみ対象パスはスキャナー側の設定次第)。

この機能はアプリ単体では動作せず、以下のAPI仕様を満たす**REST APIサーバーを別途自分で用意して自己ホストする**必要があります。EverythingXなど他の連携機能とは無関係・無依存です。参照実装(Flask + SQLite)は非公開ですが、以下の仕様を満たせば任意の言語・フレームワークで自作したサーバーでも利用できます。書庫管理機能だけは、カタログへの書き込み(スキャン結果の投入)も自分で実装する必要があります(後述)。

## クライアント側の設定

アプリの「設定 > その他の設定 > 栞同期の設定」で、サーバーのHost/Port/User/Passを入力します(User/Passは任意、HTTP Basic認証を使う場合のみ)。この1箇所の設定で栞・既読位置・履歴・書庫管理すべての同期に使われます。「設定 > その他の設定 > 栞同期の設定」内の個別チェックボックスで、4つの機能をそれぞれ有効/無効にできます。

## エンドポイント一覧

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/bookmarks?host=<host>` | 指定ホストの栞一覧を取得(`host`省略時は全件) |
| POST | `/bookmarks` | 栞を1件upsert |
| DELETE | `/bookmarks` | 栞を1件削除 |
| GET | `/read_position?host=<host>&path=<path>&file=<file>` | 指定ファイルの既読位置を1件取得(無ければ404) |
| GET | `/read_position?host=<host>` | (`file`省略時)指定ホストの既読位置を全件取得(一覧画面の「同期」ボタン・書庫管理タブの「既読位置を更新」用) |
| POST | `/read_position` | 既読位置を1件upsert |
| GET | `/history?host=<host>` | 指定ホストの履歴一覧を取得(`host`省略時は全件) |
| POST | `/history` | 履歴を1件upsert |
| DELETE | `/history` | 履歴を1件削除 |
| GET | `/library?offset=<n>&limit=<n>` | 書庫カタログをページング取得 |
| POST | `/library/rescan` | サーバー側スキャナーに即時スキャンを要求する(完了は待たない) |
| GET | `/health` | 疎通確認(任意) |

### GET /bookmarks

指定ホスト(省略時は全ホスト)の栞一覧をJSON配列で返す。

```
GET /bookmarks?host=100.122.74.51
```

レスポンス例:

```json
[
  {
    "host": "100.122.74.51",
    "path": "/Manga/SeriesName/",
    "file": "vol1.zip",
    "page": 42,
    "image": "00042.jpg",
    "chapter": -1,
    "pagerate": -1,
    "dispname": "お気に入りシーン",
    "type": 0,
    "date": 1735689600
  }
]
```

### POST /bookmarks

栞を1件upsertする。主キーは `(host, path, file, page)` — 同じ組み合わせで再度POSTすると上書きされる。

リクエストボディ(JSON、`host`/`path`/`file`/`page`は必須):

```json
{
  "host": "100.122.74.51",
  "path": "/Manga/SeriesName/",
  "file": "vol1.zip",
  "page": 42,
  "image": "00042.jpg",
  "chapter": -1,
  "pagerate": -1,
  "dispname": "お気に入りシーン",
  "type": 0,
  "date": 1735689600
}
```

成功時は `{"status": "ok"}` などのJSONを返せばよい(クライアントはHTTP 200のみ確認し、ボディの内容は特に見ない)。

### DELETE /bookmarks

栞を1件削除する。リクエストボディ(JSON): `{"host", "path", "file", "page"}`。

### GET /read_position

指定ファイル1件の既読位置を返す。`host`/`file`は必須(`path`は空でもよい)。

```
GET /read_position?host=100.122.74.51&path=/Manga/SeriesName/&file=vol1
```

- 見つかった場合: HTTP 200、以下の形式のJSONを1件返す。
- 見つからない場合: HTTP 404。

```json
{
  "host": "100.122.74.51",
  "path": "/Manga/SeriesName/",
  "file": "vol1",
  "page": 22,
  "maxpage": 40,
  "chapter": -1,
  "pagerate": -1,
  "date": 1735689600
}
```

**注意**: クライアントは`file`を拡張子を除いた状態で送信する(ZIP/RARなど拡張子違いの同一ファイルを同一視するため)。サーバー側は受け取った文字列をそのままキーとして扱えばよく、拡張子の処理は不要。

### GET /read_position (一覧モード)

`file`を省略すると一覧モードになる。`host`省略時は全件、指定時はそのホスト分のみを返す。通常のファイル一覧の「同期」ボタンと、書庫管理タブの「既読位置を更新」メニューで使われる。

```
GET /read_position?host=100.122.74.51
```

レスポンス: 単一レコードと同じ形式のJSON配列(404にはならず、0件でも`[]`を返す)。

### POST /read_position

既読位置を1件upsertする。主キーは `(host, path, file)`(`page`は主キーに含まない = 1ファイルにつき常に最新の1件のみ保持)。`host`/`path`/`file`は必須。

リクエストボディ(JSON):

```json
{
  "host": "100.122.74.51",
  "path": "/Manga/SeriesName/",
  "file": "vol1",
  "page": 22,
  "maxpage": 40,
  "chapter": -1,
  "pagerate": -1,
  "date": 1735689600
}
```

### GET /history

指定ホスト(省略時は全ホスト)の履歴一覧をJSON配列で返す。レスポンス形式は栞(GET /bookmarks)と同じ(`host`/`path`/`file`/`page`/`image`/`chapter`/`pagerate`/`dispname`/`type`/`date`)。

```
GET /history?host=100.122.74.51
```

### POST /history

履歴を1件upsertする。主キーは `(host, path, file)`(栞と違い`page`は主キーに含まない = 1ファイルにつき常に最新の1件のみ保持。開き直すたびに同じ行が上書きされる)。`host`/`path`/`file`は必須。リクエストボディの形式は栞(POST /bookmarks)と同じ。

### DELETE /history

履歴を1件削除する。リクエストボディ(JSON): `{"host", "path", "file"}`。

### GET /library

書庫カタログをページングで取得する。`offset`/`limit`はいずれも省略可(デフォルト`offset=0`、`limit`は実装依存だがクライアントは500件区切りで全件を取得し切るまでループする)。

```
GET /library?offset=0&limit=500
```

レスポンス例:

```json
{
  "total": 1234,
  "offset": 0,
  "limit": 500,
  "results": [
    {
      "path": "/Manga/SeriesName/",
      "name": "vol1.zip",
      "size": 52428800,
      "date_modified": 1735689600,
      "work_title": "SeriesName"
    }
  ]
}
```

- `work_title`は**必須**。巻数表記(`v01`/`第1巻`等)やシリーズ共通のフォルダ名などから、同じ作品の巻をグルーピングするためにサーバー側で算出してクライアントへ返す値(算出方法・手動補正の仕組みはサーバー実装側の自由)。クライアントはこの値でグルーピングするだけで、タイトル抽出ロジックは持たない。
- `path`は**ディレクトリのみ**(末尾にファイル名を含めない)。`name`はファイル名(拡張子込み)。
- `total`はクライアントがページングを終了する条件として使われるため、全件数を正しく返す必要がある。

**書庫カタログへの書き込みについて**: アプリ自身はこのエンドポイントへ書き込みを行わない(読み取り専用で利用する)。カタログの中身(どのファイルが存在するか)を用意するのは、SMB共有を定期的にスキャンしてこのAPIサーバーのデータストアへ反映する、**サーバー運用者側が別途用意するスキャナー処理の責務**になる(参照実装では、別プロセスがSMB共有をスキャンし、サーバーの内部データストアを直接更新している)。

### POST /library/rescan

サーバー側のスキャナーに即時スキャンを要求する(完了を待たない、非同期)。

- 新規にスキャンを開始できた場合: HTTP 202
- 直近に実行済みでクールダウン中の場合: HTTP 429
- それ以外の失敗: 202/429以外のステータス

実装はスキャナーの起動トリガーを立てるだけでよく、スキャン自体の完了をこのレスポンスで待つ必要はない(クライアントは完了を待たず、ユーザーが後で「端末側を更新」的な操作でGET /libraryを呼び直す前提)。

## 認証

「栞同期の設定」にUser/Passを入力した場合、クライアントは全リクエストにHTTP Basic認証ヘッダーを付与する。サーバー側で認証を必須にするかどうかは任意(Tailscale等の閉域網内運用であれば無認証でもよい)。

## 通信仕様上の注意

- クライアントは既読位置の取得(GET /read_position)を**ファイルを開く直前に同期的に**行い、サーバー側に値があればローカルの値より優先して復元する。タイムアウトは1.5秒程度を想定しているため、サーバーは低レイテンシで応答できることが望ましい。
- 既読位置の送信(POST /read_position)は、ページ送りのたびではなく、ビューアの一時停止または明示的に閉じるタイミングでベストエフォート送信される。送信失敗時のリトライは行われない。
- 栞の一覧取得(GET /bookmarks)は、栞タブを開くたびに実行され、サーバー側の内容で該当ホスト分のローカル表示を置き換える(サーバーを正とするモデル)。
- 履歴の一覧取得(GET /history)も栞と同様、履歴タブを開くたびに実行される。
- 書庫管理タブの「サーバー側を更新」(POST /library/rescan)と「端末側を更新」(GET /library全件取得)は別操作であり、スキャンの完了を自動で待ち合わせる仕組みは無い(スキャンは数十秒〜数分かかるため)。ユーザーが手動で「サーバー側を更新」→少し待つ→「端末側を更新」の順に操作する前提。
